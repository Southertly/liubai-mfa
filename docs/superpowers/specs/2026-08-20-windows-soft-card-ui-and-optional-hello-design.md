# 留白 MFA Windows 柔和卡片界面与可选启动验证设计规格

日期：2026-08-20

目标平台：Windows 11 x64

技术栈：WinUI 3、C#、.NET 8、Windows App SDK

状态：设计章节已由用户确认，等待规格复核

## 1. 背景

留白 MFA Windows 版已经具备账户管理、二维码导入、搜索与分组、Windows Hello 解锁、自动锁定、本地加密存储和加密备份。当前功能结构可用，但界面的间距、卡片层级、字体、边界和状态反馈仍显粗糙；同时，应用启动时无条件要求 Windows Hello，用户无法选择是否启用启动保护。

本次工作同时解决两个问题：

1. 将当前界面重设计为适合 10～30 个账户的“柔和卡片”风格，提升完成度和 Windows 11 原生感。
2. 将“打开应用时使用 Windows Hello”改为用户主动开启的可选功能；未开启时，打开应用不得弹出系统验证。

本规格只覆盖 Windows 客户端，不修改 Android、HarmonyOS 或其他平台代码。

## 2. 已确认决策

- 产品气质：原生、安静、可靠。
- 视觉方案：柔和卡片，而非最紧凑列表或偏安全工具的厚重界面。
- 常见账户规模：10～30 个。
- 当前首要问题：视觉粗糙。
- 启动保护：默认关闭，只有用户主动开启后才在打开应用时调用 Windows Hello。
- 敏感操作：查看 MFA 密钥和导出加密备份仍单独进行 Windows Hello 验证。

## 3. 目标

1. 通过统一的视觉资源、排版、留白、卡片和原生状态反馈消除粗糙感。
2. 在柔和视觉与 10～30 个账户的浏览效率之间取得平衡。
3. 让搜索、分组、验证码和复制仍保持高频操作优先级。
4. 支持浅色、深色、高对比度、键盘、鼠标、触摸和屏幕阅读器。
5. 未开启启动保护时，打开或重新打开应用不调用 Windows Hello。
6. 开启启动保护后，保留启动解锁、手动锁定和离开一分钟自动锁定。
7. 保留现有密钥加密、备份、锁定清理和敏感剪贴板失败策略。

## 4. 非目标

- 不新增云同步、用户账号、联网服务或在线图标下载。
- 不修改 MFA 密钥、设备密钥或备份文件格式。
- 不改变 TOTP 算法、二维码解析或账户排序规则。
- 不引入第三方 UI 控件库，也不完整重写 WinUI 标准控件模板。
- 不为视觉效果延迟锁定、复制、搜索、切换分组等高频操作。
- 不把可选 Windows Hello 设置描述为能够防御已完全控制当前 Windows 用户会话的攻击者。

## 5. 设计原则

### 5.1 原生优先

优先使用 WinUI 3 的系统主题资源、标准控件、视觉状态和系统强调色。窗口使用 Mica 作为支持环境下的背景层级，不支持时退回系统背景色。所有颜色必须来自主题资源或集中定义的主题资源，不在页面中散落硬编码浅色或深色值。

### 5.2 柔和但不臃肿

卡片以轻描边、柔和底色、12 个有效像素圆角和有限留白建立层级，不使用大面积阴影、渐变或漂浮效果。单张卡片目标高度约 84～92 个有效像素；默认窗口应看到约 5～6 张完整卡片，并能快速滚动其余账户。

### 5.3 验证码优先

账户卡片的视觉顺序为服务标识、服务与账户信息、验证码、剩余时间和复制操作。六位验证码是卡片中对比度和字号最高的内容，但不得在状态提示、日志或错误消息中回显。

### 5.4 高频操作不加负担

搜索、分组、复制和键盘快捷操作必须立即响应。动效只用于帮助理解状态变化，不得为了“有动效”而增加等待、缩放或弹跳。

### 5.5 安全状态必须真实

界面只能在启动保护实际开启时显示“Windows Hello 保护”。关闭时显示“本机加密存储”，避免把 DPAPI 本地加密和可选启动验证混为一谈。

## 6. 窗口与整体结构

### 6.1 默认窗口

- 默认普通窗口目标尺寸约为 `560 × 780` 有效像素，以容纳柔和卡片和约 5～6 个完整账户。
- 最小普通窗口目标尺寸约为 `480 × 620` 有效像素。
- 继续保存和恢复用户上次的普通窗口位置与尺寸，并限制在当前显示器工作区内。
- 不依赖最大化完成任何核心操作。
- 尺寸换算继续考虑 DPI，避免直接把有效像素当作物理像素。

### 6.2 页面层级

主界面从上到下包括：

1. 原生标题栏和 Mica 背景层。
2. 页面标题、保护状态和紧凑命令区。
3. 全宽搜索框。
4. 横向分组筛选。
5. 柔和账户卡片列表或空状态。
6. 本机保护状态与备份入口。

## 7. 主界面设计

### 7.1 顶部工作区

页面标题继续使用“验证码”。命令区提供：

- 导入二维码；
- 设置；
- 添加账户；
- 仅在启动保护开启时显示的“立即锁定”。

添加账户使用强调按钮层级，其余为普通紧凑图标按钮。每个按钮都必须包含简体中文工具提示、`AutomationProperties.Name`、键盘焦点和禁用状态。

保护状态以短文本或轻量状态标识显示：

- 未开启：`启动保护未开启`；
- 已开启：`Windows Hello 保护已开启`。

状态标识不得抢夺验证码的视觉焦点。

### 7.2 搜索与分组

搜索框占据内容区完整宽度，搜索服务名称、账户名称和分组。输入后立即在本机过滤，不显示额外加载动效。

分组使用轻量圆角筛选项，显示“全部”及其他分组的账户数量。选中态使用系统强调色的克制填充；分组较多时横向滚动，但“全部”始终容易返回。

### 7.3 账户卡片

每张卡片包含：

1. 约 40 × 40 的圆角方形服务标识，继续使用本地生成的文字与颜色，不联网下载图标。
2. 服务名称，使用半粗体和主文字色。
3. 账户名称与可选分组，使用次级和三级文字色，超长时单行省略。
4. 六位验证码，使用 Windows 可用的等宽字体并保持数字分组。
5. 细进度条，嵌入卡片底部或验证码区域下方。
6. 明确的复制按钮；点击验证码区域也可复制。
7. 编辑、查看密钥和删除继续放在上下文菜单或触摸滑动操作中，避免常驻占位。

进度条平时使用系统强调色，最后 5 秒切换到系统警示色；颜色变化同时保留剩余时间的可访问文本，不能只依赖颜色传达状态。

### 7.4 空状态与无结果状态

- 无账户：显示简短说明以及“添加账户”“导入二维码”两个操作。
- 搜索无结果：显示“没有匹配的账户”和“清除搜索和筛选”。
- 空状态不使用远程插图；可使用系统图标和轻量说明保持原生感。

### 7.5 底部状态区

底部左侧根据实际设置显示：

- 未开启启动保护：`本机加密存储`；
- 已开启启动保护：`本机加密 · Windows Hello 保护`。

底部右侧保留“备份与恢复”。任何复制恢复密钥的入口必须继续消费实际剪贴板结果；复制失败时一次提示、不自动重试，并且不得错误启用后续保存操作。

## 8. 添加、编辑与敏感信息弹窗

添加和编辑账户继续使用原生 `ContentDialog`，统一字段间距、标题、帮助文本和验证错误位置。

- 服务名称、账户和分组使用标准文本框。
- MFA 密钥输入默认遮挡，允许用户主动短暂显示。
- 粘贴 `otpauth://` 地址后继续沿用现有解析与校验逻辑。
- 添加账户本身不调用 Windows Hello。
- 编辑账户不调用 Windows Hello。
- 查看原始 MFA 密钥仍先调用 Windows Hello，取消或失败时不打开密钥对话框。
- 所有对话框关闭、取消或应用锁定后都必须清除持有的敏感文本引用。

## 9. 可选 Windows Hello 启动保护

### 9.1 设置项

在设置界面新增开关：`打开应用时使用 Windows Hello`。

设置值是非敏感偏好，保存在 Windows 应用本地设置中。缺少该设置时按 `关闭` 处理，因此更新后的首次打开不得主动弹出 Windows Hello。主界面以非阻塞、克制的方式说明启动保护尚未开启，只有用户主动操作时才请求系统验证。

### 9.2 开启

开启流程：

1. 用户打开设置并主动打开开关。
2. 应用检查 Windows Hello 是否可用。
3. 应用调用一次 Windows Hello，理由为“验证身份以开启留白 MFA 启动保护”。
4. 只有验证成功且当前会话仍有效时才持久化 `开启`。
5. 取消、失败、异常或会话失效时保持 `关闭`，并显示不含敏感信息的克制提示。

### 9.3 关闭

关闭流程：

1. 已开启状态下，用户主动关闭开关。
2. 应用调用 Windows Hello，理由为“验证身份以关闭留白 MFA 启动保护”。
3. 只有验证成功且当前会话仍有效时才持久化 `关闭`。
4. 取消、失败、异常或会话失效时保持 `开启`。

### 9.4 启动与恢复

启动流程为：

```text
读取启动保护设置
├─ 关闭 → 解密本机账户数据 → 直接显示主界面
└─ 开启 → 显示锁定页 → Windows Hello 成功 → 解密并显示主界面
```

保护关闭时：

- 启动和重新打开应用不调用 Windows Hello；
- 窗口短暂失焦或离开超过一分钟不进入锁定页；
- 顶部不显示“立即锁定”；
- 本机账户数据仍由现有 Windows 用户边界和加密存储保护。

保护开启时：

- 保留当前启动解锁；
- 保留手动锁定；
- 保留离开一分钟后的自动锁定；
- 锁定时立即使会话失效、停止计时器、关闭敏感对话框、卸载 ViewModel 并隐藏账户内容；
- 不播放会延迟敏感信息清除的退场动画。

若设置为开启但 Windows Hello 暂时不可用，应用保持锁定并提供重试和前往 Windows 设置的说明，不自动绕过保护。

### 9.5 敏感操作不随启动保护关闭

下列操作继续使用现有独立 Windows Hello 验证：

- 查看 MFA 原始密钥；
- 导出加密备份；
- 现有策略明确要求重新验证的其他敏感操作。

启动保护开关只决定“进入主界面前是否验证”，不改变这些操作的安全边界。

## 10. 状态与数据流

实现应把设置存储、策略判断和 WinUI 编排分开：

- WinUI 适配层负责读写 Windows 应用本地设置。
- 可独立测试的策略层负责判断启动是否要求验证、锁定按钮是否可见、失焦是否启动锁定计时，以及敏感操作是否仍要求验证。
- `MainWindow` 只编排窗口生命周期、系统验证、会话保护和视图切换。
- 主界面继续通过现有 ViewModel 和加密仓库加载、搜索、筛选和保存账户。

直接进入主界面与 Windows Hello 解锁成功必须汇合到同一条“加载数据并建立当前会话”路径，避免两套加载逻辑产生安全差异。

设置写入必须在系统验证成功之后进行。若持久化失败，界面保持原状态并提示“设置未保存，请重试”，不能只更新开关外观。

## 11. 动效与反馈

### 11.1 允许的动效

- 卡片悬停和按下状态使用 WinUI 原生视觉状态，目标过渡约 120ms。
- 信息提示、设置面板和普通内容状态可使用不超过约 200ms 的淡入或位移动效。
- 只有在系统允许动画时播放自定义动效；关闭系统动画后应直接切换状态。

### 11.2 禁止的动效

- 复制验证码时不缩放、不弹跳、不延迟写入剪贴板。
- 搜索和分组切换不播放逐项入场动画。
- 验证码每秒更新不触发布局动画。
- 锁定、会话失效和敏感文本清除不播放退场动画。

复制成功或失败继续通过状态提示表达，不在提示中显示验证码、密钥或恢复密钥。

## 12. 可访问性与主题

- 所有文字使用简体中文，标准算法名、协议名和 Windows Hello 除外。
- 图标按钮提供工具提示和 `AutomationProperties.Name`。
- 账户卡片的可访问名称包含服务、账户、验证码和剩余秒数，但锁定时必须随视图卸载一起清除。
- 使用系统焦点视觉，不移除键盘可见焦点。
- 支持 Tab、Shift+Tab、Enter、Space、方向键和现有复制快捷键。
- 浅色、深色和高对比度下不得出现硬编码导致的低对比文字、不可见描边或错误背景。
- 最低命中区域遵循 WinUI 桌面控件尺寸；触摸操作不依赖仅悬停可见的入口。

## 13. 错误处理

- Windows Hello 取消：视为用户未完成操作，不描述为系统故障。
- Windows Hello 暂时不可用：提供重试和系统设置指引，不泄露账户信息。
- 设置存储失败：恢复开关原状态，显示克制警告。
- 本机数据解密失败：保持阻断状态，不显示为空账户，不允许用空数据覆盖原文件。
- 剪贴板写入失败：单次失败即提示，不自动重试，不显示成功提示。
- 应用锁定或会话失效：取消未完成操作，清除敏感引用，迟到回调不得恢复旧会话内容。

## 14. 实现边界

预计只修改 Windows 范围内的以下类型文件：

- `App.xaml`：集中主题、间距、卡片和按钮资源。
- `MainWindow.xaml` / `MainWindow.xaml.cs`：背景、启动保护编排和窗口生命周期。
- `Views/AuthenticatorView.xaml`：柔和卡片主界面。
- `Views/LockView.xaml`：与新视觉统一的锁定页。
- Windows 设置视图或对话服务：启动保护开关。
- Windows 平台策略与回归项目：可独立测试的设置和保护决策。

不得把用户现有的 `Package.appxmanifest` 未提交改动混入本次提交。不得修改其他平台目录。

## 15. 验证计划

### 15.1 自动验证

至少覆盖：

1. 缺少设置时启动保护为关闭。
2. 关闭时启动不要求 Windows Hello。
3. 开启时启动要求 Windows Hello。
4. 开启验证成功、取消、失败和异常。
5. 关闭验证成功、取消、失败和异常。
6. 设置写入失败时不产生界面与持久化状态分裂。
7. 关闭时失焦不启动自动锁定，开启时保留一分钟自动锁定。
8. 添加和编辑账户不要求 Windows Hello。
9. 查看密钥和导出备份仍要求 Windows Hello。
10. 锁定后旧会话和迟到回调无效。
11. 验证码、MFA 密钥和恢复密钥复制失败继续执行一次失败即提示、无自动重试策略。

运行现有 Core Regression、Platform Regression、代码边界检查和 Windows x64 Release 构建。

### 15.2 真实应用验证

在实际 MSIX 应用中检查：

- 设置关闭时首次启动和重启均不出现 Windows Hello；
- 设置开启后重启、手动锁定和离开一分钟均要求验证；
- 添加账户不会额外要求验证；
- 设置开关的取消与失败路径不会显示错误状态；
- 默认窗口可清晰浏览约 5～6 张卡片，10～30 个账户时搜索与分组顺畅；
- 浅色、深色、高对比度和系统动画关闭状态；
- 鼠标、键盘、触摸/触控板滑动和屏幕阅读器名称；
- 锁定时账户内容立即消失，敏感弹窗关闭；
- 复制验证码、复制密钥和复制恢复密钥的成功与失败反馈。

完成验证后，保留最终通过检查的应用实例运行，供用户直接体验。

## 16. 完成标准

以下条件全部满足才算完成：

1. 用户确认本规格。
2. 柔和卡片 UI 在浅色、深色和高对比度下均无明显粗糙或错位。
3. 未开启启动保护时，打开应用不弹 Windows Hello。
4. 开启启动保护后，原有启动、手动和超时锁定行为有效。
5. 敏感操作、加密存储、备份和剪贴板失败策略未退化。
6. 自动回归、代码检查和 Windows x64 Release 构建通过。
7. 真实 MSIX 启动与主要交互路径完成验证。
8. 用户现有 `Package.appxmanifest` 改动和其他平台代码保持不变。
