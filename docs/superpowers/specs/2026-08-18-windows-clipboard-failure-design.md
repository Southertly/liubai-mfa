# Windows 剪贴板失败保护设计

## 背景

Windows 真实界面测试稳定复现了一个崩溃：复制验证码后，应用在下一次界面交互时退出。Windows 错误报告记录的底层异常为 `0x800401D0`，表示剪贴板暂时无法打开；当前 `Clipboard.SetContent` 与 `Clipboard.Flush` 调用没有错误边界，异常最终由 WinUI 终止进程。

## 目标

- 剪贴板暂时不可用时，应用保持运行。
- 只有复制真实成功时才显示“验证码已复制。”。
- 复制失败时显示“剪贴板暂时不可用，请稍后重试。”，不包含验证码、密钥或系统异常详情。
- 查看 MFA 密钥时，复制失败不得显示“密钥已复制”，改为显示同一条克制警告。
- 导出备份时，恢复密钥复制失败不得显示成功，也不得启用“保存备份文件”；按钮应提示重试。
- 保持一次点击只尝试一次复制，不增加后台重试和新的并发状态。

## 方案

新增一个职责单一的剪贴板服务，将 `DataPackage`、`Clipboard.SetContent` 和 `Clipboard.Flush` 封装在同一个错误边界内。服务返回成功或失败结果，不向界面层传播剪贴板异常，也不记录待复制内容。

新增纯 `ClipboardResultPolicy`，把成功/失败布尔值映射为验证码与 MFA 密钥的状态提示，以及恢复密钥按钮文字和“能否继续保存”状态。界面只应用这个经过行为测试的结果，避免用源码字符串检查代替真实状态验证。

`MainWindow` 的验证码复制流程根据结果显示成功或警告提示。账户密钥对话框和恢复密钥对话框把复制回调改为返回成功结果：账户密钥失败时显示警告；恢复密钥失败时保持保存按钮禁用并允许再次复制。账户查找、解锁会话校验和密钥清理行为保持不变。

## 数据流

1. 用户点击账户行的复制按钮或使用现有复制快捷键。
2. 主窗口确认当前仍处于有效解锁会话，并读取当前验证码。
3. 剪贴板服务执行一次写入和持久化。
4. 写入成功时显示成功提示；发生剪贴板边界异常时显示克制的警告提示。

查看 MFA 密钥和导出恢复密钥复用同一个剪贴板服务结果。恢复密钥只有复制成功后，才能启用备份保存操作。

## 错误与安全边界

- 剪贴板边界内的系统互操作失败被转换为失败结果，避免未处理异常进入 WinUI 事件循环。
- 不在错误信息、日志或测试输出中包含验证码和 MFA 密钥。
- 不自动重试，避免延长敏感数据在闭包或后台任务中的驻留时间。
- 不改变锁定、Windows Hello、账户存储或备份逻辑。

## 测试与验收

- 先增加回归测试，证明模拟剪贴板写入异常时旧实现缺少安全结果边界。
- 测试覆盖成功结果、剪贴板异常转失败结果、非空输入校验以及写入只调用一次。
- 回归检查覆盖验证码、MFA 密钥和恢复密钥三个入口都消费布尔结果，不允许忽略失败后显示成功。
- 纯策略行为测试必须证明：失败只产生警告或禁用状态；成功才产生成功或启用状态。
- Core、Platform、CodeBehindCheck、真实 WinUI XAML 和完整 Release x64 构建全部通过。
- 重新生成并安装测试 MSIX；使用纯测试账户复现“复制验证码 → 切换分组”，应用不得退出。
- 成功路径显示成功提示；失败路径只显示克制的警告提示。

## 非目标

- 不实现自动重试、剪贴板历史管理或自动清空剪贴板。
- 不修改 Android、HarmonyOS 或其他 Git 分支。
