# Windows MFA 添加账户入口与截图扫描设计

## 背景

当前账户列表页同时放置“导入二维码”和“添加账户”两个入口，新增方式被拆散在不同按钮中；原生标题栏还重复显示应用名称。用户希望减少首页噪声，并将截图扫描、图片导入和手动输入统一收进“＋”入口。

## 目标

- 原生标题栏不显示应用图标和名称，只保留可拖动区域及系统窗口控制按钮。
- 首页移除独立的二维码图片导入按钮，所有新增方式统一从“＋”进入。
- “＋”打开当前窗口内的完整“添加账户”页面，不使用拥挤的下拉菜单或嵌套弹窗。
- 新增“截图并扫描二维码”，允许用户框选屏幕上的二维码并在本机完成识别。
- 继续保留“从图片导入”和“手动输入”，并复用现有确认、保存和错误处理能力。

## 非目标

- 不实现摄像头连续扫描。
- 不支持一次截图导入多个二维码。
- 不把“导入备份”放进添加账户页面。
- 不保存截图、不上传截图、不通过剪贴板传递截图。
- 不改变 TOTP 生成、账户加密存储或备份格式。

## 首页与标题栏

### 标题栏

主窗口使用自定义标题栏：隐藏原生应用图标和“留白 MFA”文字，保留系统最小化、最大化和关闭按钮。标题栏的空白区域作为窗口拖动区，双击行为继续交给系统处理。

### 首页操作区

- 移除顶部独立的“导入二维码”按钮。
- 保留“启动保护设置”。
- “立即锁定”仍按现有保护状态决定是否显示。
- “＋”作为唯一的新增账户入口。
- 空账户状态也只显示一个“添加账户”按钮，并进入同一添加账户页面。

## 添加账户页面

点击“＋”后，主窗口从账户列表切换到完整的“添加账户”页面。页面包含：

1. 顶部返回按钮和标题“添加账户”。
2. 主操作卡片“截图并扫描二维码”，说明为“框选屏幕上的二维码，识别后可确认账户信息”。
3. 次级方式“从图片导入”，复用现有图片文件选择和二维码识别流程。
4. 次级方式“手动输入”，复用现有账户输入对话框。

返回按钮和 `Esc` 回到账户列表，并恢复进入页面前的搜索、分组和滚动位置。页面只设置一个主操作，其他导入方式使用同一层级的次级列表项。

## 截图扫描交互

### 系统能力

截图扫描使用 Windows 11 当前的 Snipping Tool 协议：

```text
ms-screenclip://capture/image
  ?rectangle
  &enabledModes=RectangleSnip
  &api-version=1.2
  &user-agent=LiubaiMfa
  &redirect-uri=liubai-mfa://capture-response
  &x-request-correlation-id=<guid>
```

应用必须通过 `Launcher.LaunchUriAsync` 启动截图工具，并在 MSIX 清单中注册 `liubai-mfa` 协议回调。协议响应通过一次性 `file-access-token` 返回截图文件。设计依据：[Microsoft Learn：Launch Snipping Tool](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-snipping-tool)。

### 用户流程

1. 用户点击“截图并扫描二维码”。
2. 应用记录本次请求的关联 ID，并启动系统矩形截图界面。
3. 用户框选二维码后，Snipping Tool 通过协议重新激活应用。
4. 应用核对响应关联 ID、状态码和文件访问令牌。
5. 应用只在内存中读取截图并调用现有二维码解码能力，不复制到本地目录。
6. 识别成功后显示现有账户确认界面；用户确认后才保存账户。
7. 保存成功后回到账户列表并显示克制的成功提示。

### 取消与失败

- `499` 用户取消：安静返回添加账户页面，不显示警告。
- `400` 请求无效：提示“截图功能暂时不可用，请使用图片导入或手动输入”。
- `408` 超时：提示“截图已超时，请重新截图”。
- `500` 或启动失败：提示“未能打开截图工具，请使用图片导入或手动输入”。
- 截图中没有可识别的 TOTP 二维码：提示“选区中没有可识别的 TOTP 二维码”，并提供“重新截图”。
- 回调缺少令牌、令牌兑换失败或关联 ID 不匹配：拒绝处理，不显示截图内容；关联 ID 不匹配视为过期回调。

## 自动锁定与会话安全

启动截图工具会使主窗口失活，现有自动锁定规则继续生效，不为截图流程创建豁免：

- 如果截图返回时会话仍有效，立即处理回调。
- 如果应用已自动锁定，只在内存中保留已验证的待处理回调；用户通过 Windows Hello 解锁后再兑换一次性文件令牌并识别。
- 如果用户取消解锁、应用退出或待处理请求被新请求替代，放弃该回调。
- 任意时刻只允许一个截图请求处于等待状态；新请求必须先清除旧请求状态。
- 不在日志、状态提示或持久化设置中记录截图路径、二维码内容、密钥或文件令牌。

## 组件边界

### `AddAccountView`

新建独立用户控件，仅负责展示添加方式并发出以下意图：

- `BackRequested`
- `ScreenshotScanRequested`
- `ImportImageRequested`
- `ManualEntryRequested`

它不直接访问文件、截图协议、二维码解析或账户存储。

### `SnippingToolCaptureService`

负责生成截图请求、启动 Snipping Tool、校验关联 ID 和解析协议状态。它不负责二维码识别或账户保存。

### 协议激活路由

`App` 同时处理冷启动和已运行实例的协议激活，将合法的截图响应交给主窗口。协议路由不直接操作视图，并忽略非本应用回调路径。

### 二维码导入协调

截图扫描和图片导入在获得 `StorageFile` 后进入同一条管线：读取图片 → 解码 `otpauth://` → 解析账户草稿 → 用户确认 → 保存 → 刷新列表。这样避免维护两套错误提示和保存规则。

### 主窗口导航

`MainWindow` 只协调账户列表、添加账户页和锁定页三种可见状态。切换到添加账户页时保留账户列表视图模型，不卸载账户数据。

## 动效与可访问性

- 点击“＋”进入页面使用 160–200ms 的轻微横向位移与淡入，返回方向相反；键盘触发时不播放位移动效。
- 所有按钮提供按下反馈，动效只修改 `transform` 和 `opacity`。
- 遵循系统“减少动态效果”设置；开启后只保留必要淡入。
- 图标使用一致的 Windows 字形或矢量图，不使用表情符号。
- 图标按钮保留可见工具提示和 `AutomationProperties.Name`。
- 返回、截图扫描、图片导入和手动输入均可通过键盘访问，焦点顺序与视觉顺序一致。

## 浏览器评审镜像

现有浏览器评审镜像同步以下变化，但仍只使用虚构数据：

- 标题栏隐藏应用名称。
- 首页移除独立图片导入按钮。
- 点击“＋”切换到可交互的“添加账户”页面。
- 添加账户页展示截图扫描主入口、图片导入和手动输入。
- 点击返回按钮或按 `Esc` 回到账户列表。
- 浏览器镜像不调用真实截图工具，不读取本机文件，也不生成或保存账户。

## 清单文件保护边界

协议回调需要修改 `Package.appxmanifest`。该文件当前包含用户未提交改动，实现时必须先检查并保留现有差异，只增加协议扩展所需的独立节点；不得覆盖、还原或把无关清单差异混入功能提交。

## 验证策略

### 自动验证

- 截图响应状态策略：覆盖 `200`、`400`、`408`、`499`、`500`、缺少令牌和关联 ID 不匹配。
- 会话策略：覆盖有效会话立即处理、锁定后等待解锁、取消解锁放弃、新请求替换旧请求。
- 导入协调：截图文件与图片文件必须进入同一解析和确认流程。
- XAML/源契约：标题栏无名称、首页无独立图片导入、添加账户页存在三种方式和返回路径。
- 继续运行现有 Platform、Core、CodeBehind、WinUI x64 和解决方案回归。

### 打包应用验证

- 使用正式 MSIX 身份验证协议回调的冷启动与热激活。
- 矩形截图包含有效二维码时进入确认并成功保存。
- `Esc` 取消截图时无错误提示。
- 截图超过自动锁定时限后，先完成 Windows Hello 解锁再继续识别。
- 无二维码、截图工具不可用和超时均显示对应恢复路径。
- 截图不出现在应用 LocalState、剪贴板或自动保存目录中。
- 标题栏可拖动、双击最大化，系统窗口按钮正常工作。
