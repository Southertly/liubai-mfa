# Windows MFA 内置浏览器评审镜像设计

## 目标

在 Codex 内置浏览器中提供一份与当前 Windows MFA 正式界面视觉结构一致的静态评审镜像，方便用户直接按编号指出需要修改的区域，例如“改 ⑤ 卡片间距”。

## 范围与边界

- 更新现有浏览器预览页，不修改 WinUI 正式界面、业务逻辑或安装包。
- 只使用固定的虚构账户、虚构验证码和虚构分组，不读取或展示真实 MFA 数据。
- 页面不生成 TOTP、不访问网络、不保存输入，也不向外发送反馈内容。
- 本轮先覆盖当前正式界面的浅色、宽窗口状态；深色、高对比度和完整交互流程不在范围内。

## 页面结构

浏览器页面由“应用镜像”和“编号说明”两部分组成。应用镜像保持当前正式界面的主要层级、尺寸关系、圆角、留白和视觉密度，并标出以下七个评审区域：

1. 窗口背景与标题栏：浅蓝背景、窗口标题和整体外框。
2. 页头与操作按钮：主标题、副标题、导入、设置和新增按钮。
3. 搜索框：搜索图标、占位文案、尺寸与上下间距。
4. 分组筛选：全部、个人等筛选项及选中状态。
5. 账户卡片：服务图标、账户信息、验证码、剩余时间和复制按钮。
6. 进度与临期状态：卡片底部进度条，以及临期时的红色提示示例。
7. 页脚：自动更新说明和“备份与恢复”入口。

编号说明固定展示每个区域的名称。页面应让用户无需理解代码或控件名称，就能用“编号 + 修改意见”表达反馈。

## 视觉与交互

- 桌面宽度下，应用镜像居中展示，编号说明放在旁边；窄窗口下改为上下排列。
- 编号使用克制的高对比标记，不遮挡关键内容。
- 鼠标悬停或键盘聚焦编号时，对应区域轻微高亮；点击后保持选中，方便持续观察。
- 所有按钮和账户数据仅用于视觉演示，不触发正式功能。
- 示例账户使用 GitHub、Google、Microsoft 等通用服务名称，但账户名和六位验证码必须是明确虚构的数据。

## 验收方式

- 内置浏览器可直接打开更新后的页面，且控制台无页面错误。
- 页面完整显示 ① 至 ⑦，编号与对应区域关系清楚。
- 页面不得包含当前正式应用中的真实账户名、真实验证码或本地存储内容。
- 将镜像与当前正式应用并排观察，确认视觉层级、主要间距和卡片结构足以支持逐区评审。
- 用户可以直接回复类似“⑤ 卡片太高，验证码再靠右一点”，作为下一轮修改依据。

## 非目标

- 不在本轮直接修改 WinUI 源码。
- 不实现 Windows Hello、复制、导入、备份或验证码计算。
- 不把浏览器镜像作为产品 Web 版本发布。
