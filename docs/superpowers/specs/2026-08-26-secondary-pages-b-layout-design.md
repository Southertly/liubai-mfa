# Windows MFA 二级页面 A 方向设计

## 目标

解决添加账户、设置、锁定页在窄窗口中的排版问题：内容层级过平、多个嵌套卡片造成视觉堆叠、主操作不突出、标题区和内容区宽度不一致，以及页面变长后需要反复滚动。

## 已确认方向

采用 A 方向的“纵向聚焦”骨架作为二级页面的统一语言：

- 顶部固定返回区：返回按钮、页面标题、简短说明；不再额外放一条与标题竞争的状态标签。
- 页面主体采用统一的最大内容宽度与左右留白。
- 设置页不再增加顶部横向标签或侧栏导航，直接按“安全”“数据”“关于”纵向展示全部内容。
- 添加账户页和锁定页复用同样的返回、标题和内容起点，但不强行加入侧栏，避免简单流程被导航复杂化。
- 每个页面只保留一个主操作；其他操作使用行级次要动作或轻量按钮。

## 页面结构

### 设置页

所有窗口宽度使用同一列纵向布局：返回区、页面标题、分区标题和内容组沿主轴排列，内容过长时只使用一个纵向滚动区域，禁止出现横向滚动。

- 安全：启动保护、立即锁定。
- 数据：导入加密备份、导出加密备份。
- 关于：本地优先、版本信息和数据位置说明。

每个设置项是一行扁平的 `Button`，包含图标、标题、辅助说明、状态或箭头。每个分区只使用一层表面，不再由“外层 section Border + 内层每行 Border + 自定义阴影模板”叠加。

### 添加账户页

保留 B 的分区感但采用单列内容：

- “推荐方式”只放截图并扫描二维码，作为唯一视觉主操作。
- “其他方式”放图片导入和手动输入，两行同一组列表样式。
- 底部显示本地存储说明，不与按钮争夺注意力。

### 锁定页

使用居中的安全状态头部 + 单一解锁操作组：

- 顶部锁图标、标题、错误/说明文本。
- 解锁方式改为同一组列表行；Windows Hello 为主操作，电脑密码为次操作。
- 自动锁定说明放在操作组下方，使用辅助文本，不再单独形成卡片。

## 视觉与交互规则

- 使用现有主题资源，不在页面内写新的硬编码颜色。
- 统一 8pt 间距阶梯；触控/鼠标目标最小 44px。
- 正文不小于 12px，标题层级使用 18/24/28 的固定比例；状态、说明和版本信息使用辅助色但保证可读对比度。
- 所有操作行有明确的键盘焦点态和按下反馈；不依赖悬停表达状态。
- 页面切换保留现有安全优先的生命周期与取消逻辑；只调整视觉树和布局，不改变解锁、锁定、备份、二维码导入行为。
- 只保留轻量的透明度/位移过渡，避免给每个行项目叠加独立动画。

## 实现边界

- 修改范围：`App.xaml` 主题资源/通用样式、`Views/SettingsView.xaml`、`Views/AddAccountView.xaml`、`Views/LockView.xaml`，必要时补充对应的分区选择代码后置逻辑。
- 不修改 Android/HarmonyOS 代码，不改变 MFA 数据模型、存储、加密、认证和备份协议。
- 先完成 XAML 结构和样式，再进行 Release x64 构建、已安装 MSIX 启动和窗口截图验证。

## 验收标准

1. 设置页在当前窄窗口中不再出现顶部横向分区条，安全、数据、关于内容按纵向顺序自然阅读，不出现多层卡片套卡片的视觉堆叠。
2. 添加账户页首要动作一眼可见，三种入口不会被相同权重的按钮淹没。
3. 锁定页能快速识别“当前已锁定”和“下一步如何解锁”。
4. 浅色/深色主题都保持同一层级关系；键盘 Tab 顺序与视觉顺序一致。
5. 构建 0 警告、0 错误，应用实际启动后主窗口保持响应。
