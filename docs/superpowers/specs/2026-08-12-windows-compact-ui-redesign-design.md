# 留白 MFA Windows 紧凑界面重设计规格

日期：2026-08-12

目标平台：Windows 11 x64

技术栈：WinUI 3、C#、.NET 8、Windows App SDK

状态：设计已确认

## 1. 背景

留白 MFA Windows 版是一个本地优先的 TOTP 身份验证器。现有 Windows MVP 已实现账户管理、二维码图片导入、Windows Hello 解锁、自动锁定、密钥保护及加密备份，但主界面更接近传统大窗口应用：默认尺寸偏大、账户行操作按钮过多、深色样式采用硬编码颜色，而且缺少适合 7–20 个账户的搜索和分组筛选。

本次重设计把产品定位明确为“随手调用的小工具”：用户打开应用，迅速找到验证码，复制后离开。界面参考用户提供的移动端身份验证器截图中的分组入口、服务图标、大号验证码和倒计时进度线，但交互必须转换为原生 Windows 11 桌面模式。

## 2. 目标

1. 默认以紧凑小窗口启动，不占满屏幕。
2. 默认窗口首屏完整显示 6 个账户。
3. 用户能够通过服务名、账户名或分组快速找到验证码。
4. 验证码和复制操作成为账户行中最突出的内容。
5. 编辑、查看密钥和删除不再占用常驻按钮空间。
6. 保留现有 Windows Hello、DPAPI、本地加密存储、二维码解析和 v2 加密备份行为。
7. 支持浅色、深色、高对比度、鼠标、键盘、触摸和触控板。
8. 不增加联网依赖，不上传账户数据，不在线下载服务图标。

## 3. 非目标

- 不修改 TOTP 算法、账户数据格式、设备密钥格式或 v2 备份格式。
- 不实现云同步、用户账号、摄像头实时扫码、Windows 10 或 ARM64。
- 不引入新的 UI 框架或第三方控件库。
- 不把 Windows 版改造成多页面、大屏仪表盘或传统设置中心。
- 不复刻移动端底部导航栏和悬浮操作按钮。

## 4. 设计原则

### 4.1 验证码优先

账户列表按照“服务和账户信息 → 大号验证码 → 复制”建立视觉层级。用户无需进入详情页即可完成最常用任务。

### 4.2 原生 Windows 11

优先使用 WinUI 3 原生控件和 Fluent 资源：`ListView`、`SwipeControl`、`AutoSuggestBox` 或搜索输入控件、`InfoBar`、`ContentDialog`、`MenuFlyout`、系统主题画刷和系统强调色。避免手写标准控件的完整模板。

### 4.3 本地优先与克制提示

搜索、筛选、图标解析和状态更新均在本机完成。错误提示不得回显验证码、MFA 密钥、恢复密钥、备份正文或本地加密数据内容。

### 4.4 小窗口优先

界面必须先满足默认紧凑窗口，再考虑用户主动拉宽后的布局。不能依赖最大化才能完成任何核心操作。

## 5. 窗口与外壳

### 5.1 默认尺寸

- 首次启动的普通窗口尺寸约为 `520 × 680` 有效像素。
- 最小普通窗口尺寸约为 `460 × 560` 有效像素。
- 禁用最大化，保留最小化、关闭、移动和拖动缩放。
- 启动时不得自动铺满屏幕。
- 记录用户上次的普通窗口位置和尺寸；恢复时将窗口限制在当前显示器工作区内，避免窗口落到屏幕外。
- 不恢复最大化状态。

尺寸换算应考虑当前窗口 DPI。WinUI `AppWindow.Resize` 接收物理像素，必须根据窗口 DPI 将有效像素换算为物理像素。

### 5.2 外壳层级

窗口从上到下包括：

1. 原生标题栏。
2. 页面标题与紧凑命令区。
3. 搜索框。
4. 横向分组筛选。
5. 账户列表。
6. 本地保护状态及“备份与恢复”入口。

使用系统 Mica 或平台默认背景层级，内容区使用 WinUI 主题资源。不得继续以硬编码深色背景作为唯一主题。

## 6. 主界面

### 6.1 顶部命令

页面标题为“验证码”。右侧显示三个紧凑图标按钮：

- 从二维码图片导入；
- 立即锁定；
- 添加账户。

每个图标按钮必须提供简体中文工具提示、`AutomationProperties.Name` 和清晰的键盘焦点。添加账户使用系统强调色，另外两个命令使用普通按钮层级。

### 6.2 搜索

搜索范围包括：

- 服务名称；
- 账户名称；
- 分组名称。

输入后立即更新当前列表，不打开独立搜索页，不发起网络请求。清空搜索后恢复当前分组的完整列表。

### 6.3 分组筛选

搜索框下方显示横向筛选项：

- 全部及账户数量；
- 每个非空分组及账户数量。

点击分组只过滤当前列表，不进入新页面。分组较多时横向滚动或折叠次要分组，但“全部”始终可达。默认选中“全部”。

### 6.4 排序

首版只提供按服务名称排序，服务名称相同时按账户名称排序。排序规则稳定、大小写不敏感，不加入最近使用、拖动排序等额外模型。

### 6.5 账户行

默认窗口下单行高度约为 60 个有效像素，使首屏能完整显示 6 个账户。账户行包括：

1. 服务图标；
2. 服务名称；
3. 账户名称；
4. 六位验证码，以 `123 456` 形式显示；
5. 固定复制图标；
6. 底部 2–3 像素倒计时进度线。

服务名称和账户名称允许单行省略，完整内容通过工具提示和无障碍名称访问。验证码使用等宽或表格数字特性，更新时不导致整行布局抖动。

常见服务可使用应用内置的本地图标。未知服务使用确定性的首字母色块；不得联网获取图标。图标仅用于识别，不能成为区分账户的唯一依据。

### 6.6 复制

- 点击验证码或复制图标均复制当前验证码。
- 账户行获得键盘焦点后，`Ctrl+C` 复制当前验证码。
- 成功后以短暂、非阻塞状态提示“验证码已复制”。
- 提示不得重复显示验证码内容。

### 6.7 左滑操作

账户行使用 WinUI `SwipeControl`。向左滑动账户行，以 `Reveal` 模式露出：

1. 编辑；
2. 查看密钥；
3. 删除。

滑动本身只展示命令，不直接执行任何操作，尤其不得使用一次滑动直接删除的 `Execute` 模式。

主界面不显示常驻“更多”按钮。为保证桌面端和无障碍可用性：

- 鼠标右键显示具有相同命令的 `MenuFlyout`；
- 键盘 `Shift+F10` 显示相同菜单；
- 三个入口复用同一组命令及安全校验逻辑。

查看密钥必须再次通过 Windows Hello。删除必须显示具体服务和账户，并通过二次确认后执行。

### 6.8 新账户反馈

添加或导入成功后：

- 自动切换到能显示该账户的分组状态；
- 清理会遮蔽该账户的搜索条件，或明确提示用户清除筛选；
- 滚动到新账户；
- 使用短暂、主题兼容且不依赖颜色的高亮反馈。

## 7. 关键流程

### 7.1 锁定与解锁

锁定界面覆盖整个内容区，不显示账户名称、账户数量、分组或验证码。界面包括：

- 锁定图标；
- “验证码已锁定”；
- 对 Windows Hello 用途的简短说明；
- “使用 Windows Hello 解锁”主按钮；
- “离开 1 分钟后自动重新锁定”的说明。

Windows Hello 不可用、被取消或验证失败时，应用保持锁定。若本地账户数据无法解密，应用保持锁定并禁止写入，防止以空数据覆盖原文件。

### 7.2 添加与编辑账户

添加账户在当前紧凑窗口中使用对话式界面，包含：

- 手动输入；
- 二维码图片导入；
- 服务名称；
- 账户名称；
- Base32 密钥或 `otpauth://` 地址；
- 可选分组。

二维码图片解析成功后先填充表单，由用户确认服务、账户和分组后再保存。密钥输入在保存前可见性受控，不在错误提示或日志中回显。

编辑账户不显示或允许修改现有密钥，保持当前 MVP 的安全边界。

### 7.3 查看密钥

查看密钥由左滑或上下文菜单进入，必须再次通过 Windows Hello。密钥在独立 `ContentDialog` 中分组显示，可选择并复制。取消系统验证时只显示操作已取消，不透露密钥信息。

### 7.4 删除账户

删除命令使用动词明确的确认对话框，正文必须包含服务名称和账户名称。主按钮为“删除”，取消为次要操作。删除成功后更新筛选计数和空状态。

### 7.5 备份与恢复

主界面底部提供“备份与恢复”入口，进入同一紧凑窗口内的简单页面，包含：

- 导入加密备份；
- 导出加密备份；
- 返回验证码。

导出前再次使用 Windows Hello。生成恢复密钥后，用户必须先复制或确认已保存恢复密钥，才能继续保存备份文件。恢复密钥不写入备份文件。

导入时区分取消、密钥错误、格式无效和损坏，但提示不得暴露文件正文。去重与篡改拒绝继续复用现有核心逻辑。

## 8. 组件边界

### 8.1 `MainWindow`

仅负责：

- 窗口尺寸与位置恢复；
- 系统标题栏与窗口背景；
- Windows 激活/失活生命周期；
- 自动锁定；
- 锁定遮罩；
- 顶层页面切换。

### 8.2 验证码主视图

负责：

- 顶部命令；
- 搜索输入；
- 分组筛选；
- 排序标签；
- 账户列表；
- 空、无结果、加载和普通错误状态；
- 账户行复制、滑动和上下文命令绑定。

### 8.3 `MainViewModel`

在现有账户集合基础上增加：

- 搜索词；
- 当前分组；
- 分组计数；
- 稳定排序后的过滤结果；
- 当前焦点账户；
- 账户命令。

过滤结果是现有账户集合的派生视图，不写入新的账户数据格式。

### 8.4 对话和流程

添加、编辑、查看密钥、删除确认、备份导入和备份导出保持独立的小流程。它们通过明确输入和结果与主视图通信，不直接操作视觉树之外的其他页面状态。

### 8.5 安全与平台服务

以下服务保持职责不变：

- `EncryptedAccountRepository`；
- `WindowsSecureKeyStore`；
- `WindowsHelloService`；
- `NativeFileService`；
- `QrCodeImportService`；
- `BackupCrypto` 和 TOTP 核心逻辑。

## 9. 数据流

1. 应用启动后只显示锁定视图。
2. Windows Hello 验证成功后，仓库解密并加载账户。
3. 原始账户集合进入 ViewModel；搜索、分组和排序生成只读的显示集合。
4. 每秒计时器更新验证码、剩余秒数和进度线。
5. 复制命令只读取当前显示账户的验证码并写入系统剪贴板。
6. 添加、编辑、删除或导入通过 ViewModel 调用仓库保存，成功后刷新派生视图和计数。
7. 锁定时停止计时器、卸载 ViewModel 中的账户数据并恢复锁定遮罩。

## 10. 状态与错误处理

### 10.1 数据驱动状态

- 加载：显示“正在解锁本地账户”，不能只显示无说明的旋转图标。
- 空账户：说明尚未添加账户，并提供“添加账户”和“从二维码图片导入”。
- 搜索无结果：显示“没有匹配的账户”，并提供“清除搜索和筛选”。
- 普通错误：使用紧凑 `InfoBar`，提供可执行的恢复建议。
- 解密错误：保持锁定，禁止写入，不与普通空状态混淆。

### 10.2 提示层级

- 复制、添加、编辑、导入等成功反馈使用短暂非阻塞提示。
- 可恢复的格式或输入问题使用 `InfoBar`。
- 删除、恢复密钥确认等阻塞决策使用 `ContentDialog`。
- Windows Hello 的取消不显示成系统故障。

## 11. 主题、响应式与无障碍

### 11.1 主题

- 使用 `{ThemeResource ...}` 和 WinUI 平台画刷。
- 支持 Light、Dark 和 High Contrast。
- 进度、选择、错误和成功状态不能只依赖颜色表达。
- 高对比度下优先使用系统颜色资源，不禁用系统高对比度调整。

### 11.2 响应式

- 默认 `520 × 680` 有效像素下显示完整命令、筛选和 6 行账户。
- 窗口接近最小宽度时，服务名称和账户信息优先保留，次要文字缩短，命令仍可通过工具提示和菜单访问。
- 账户列表拥有唯一的纵向滚动区域，不在 `ListView` 外再嵌套纵向 `ScrollViewer`。
- 用户拉高窗口后显示更多账户；拉宽后增加文字空间，不改成多列卡片。

### 11.3 输入与无障碍

- 所有命令支持键盘焦点和可见焦点环。
- 图标按钮、服务图标、验证码和滑动命令提供可朗读名称。
- 左滑不是唯一入口，右键和 `Shift+F10` 提供等价命令。
- 搜索、分组、列表和底部入口具有合理的 Tab 顺序。
- 长文本省略时提供完整的工具提示和无障碍文本。

## 12. 安全边界

- 锁定状态不泄露账户元数据。
- 查看密钥和导出备份前必须进行 Windows Hello 验证。
- 本地数据解密失败时保持锁定并停止写入。
- 删除必须二次确认，滑动不得直接删除。
- 不记录验证码、MFA 密钥、恢复密钥或备份正文。
- 不将账户、搜索词、分组或服务信息发送到网络。
- 本地内置图标不得携带远程更新逻辑。

## 13. 验收与测试

### 13.1 自动验证

1. 运行现有 `LiubaiMfa.Core.Regression` 回归测试。
2. 运行现有 Windows 平台和 CodeBehind 编译检查。
3. 在 Windows 11 x64 上执行完整解决方案 Release 构建。
4. 验证 XAML 编译无警告，项目继续满足 warnings-as-errors。

### 13.2 真实启动验证

构建成功不等于完成。必须启动实际 WinUI 应用并确认：

- 出现标题为“留白 MFA”的可交互顶层窗口；
- 默认窗口约为 `520 × 680` 有效像素且未最大化；
- 最大化不可用；
- 窗口位置和普通尺寸能够恢复；
- 应用最终验证实例保持运行，除非用户要求关闭。

### 13.3 界面场景

至少验证：

- 0、6、20 个账户；
- 超长服务名称、账户名称和分组名称；
- 搜索命中、无结果、清除搜索；
- 全部和各分组筛选；
- 验证码每秒更新及进度线归零；
- 点击验证码、复制按钮和 `Ctrl+C`；
- 左滑、鼠标右键和 `Shift+F10` 的命令等价性；
- 查看密钥的验证成功、取消和失败；
- 删除的取消和确认；
- 二维码无效、重复账户和导入成功；
- 备份导入、导出、错误恢复密钥和损坏文件；
- 自动锁定以及锁定后不显示账户元数据；
- 浅色、深色、高对比度；
- 鼠标、键盘、触摸和触控板；
- 默认尺寸、最小尺寸和高 DPI 显示器。

## 14. 完成标准

当且仅当以下条件全部满足，重设计才算完成：

1. 已确认的紧凑窗口、6 行账户、搜索、分组和账户行视觉全部落地。
2. 左滑、右键、键盘命令和安全确认行为一致。
3. 现有加密、Windows Hello 和备份核心行为未退化。
4. 自动回归、Release 构建和真实启动验证通过。
5. 浅色、深色、高对比度及主要输入方式完成检查。
6. 用户能在默认小窗口中完成“解锁 → 找码 → 复制”主任务，无需最大化或进入其他页面。
