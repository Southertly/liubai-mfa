# MFA Windows 客户端 UI 重设计规格

日期：2026-08-21  
范围：Windows 版 MFA 身份验证器（WinUI 3 / C# / .NET 8）

## 1. 目标

将主界面收敛为一个紧凑、清晰、以复制验证码为核心的单列工具窗口，同时保留现有账户添加流程和本地优先的安全模型。

核心交互目标：

1. 用户打开应用后能快速搜索并复制验证码。
2. 顶部只保留“设置”和“+”两个入口。
3. 账户操作不依赖右键菜单；编辑、查看密钥、删除通过向左拖动账户标签访问。
4. 没有 Windows Hello 的设备仍可使用 Windows 系统密码解锁。

## 2. 非目标

- 不新增 Android 或 HarmonyOS 功能。
- 不新增云同步、用户账号系统或应用自定义密码。
- 不改变现有二维码截图、图片导入、手动输入的业务流程。
- 不把备份/恢复重新放回主页面底部或“+”账户添加页面。

## 3. 视觉与窗口框架

- 采用原生 Fluent 2 视觉方向。
- 主窗口使用 Mica；设置菜单等短暂浮层使用 Acrylic。
- 所有颜色、间距、圆角、字号优先使用 WinUI ThemeResource，支持浅色、深色和高对比度主题。
- 使用 Segoe UI Variable；验证码使用等宽字体以保持数字宽度稳定。
- 采用 8px 间距网格；可操作目标最小尺寸为 44x44px。
- 默认窗口约 520x680px，最小约 460x560px；保持单列布局，不引入侧边导航。
- 不使用渐变、发光或装饰性动效；锁定、关闭和敏感操作优先于动画。

## 4. 首页布局

```text
┌──────────────────────────────────────┐
│ 验证码                         设置  ＋│
│ ┌──────────────────────────────────┐ │
│ │ 搜索服务、账户或分组             │ │
│ └──────────────────────────────────┘ │
│ [全部 12] [工作 5] [个人 4]  …       │
│                                      │
│ 账户列表                             │
│                                      │
│ 本机加密保护 · 验证码每 30 秒更新     │
└──────────────────────────────────────┘
```

- 顶部操作区仅有“设置”和“+”。
- “+”继续进入现有 `AddAccountView`，不在此处重复导入入口。
- 搜索框支持按服务商、账户名和分组过滤。
- 分组筛选使用紧凑的可横向滚动标签。
- 底部只显示本机保护和验证码刷新状态，不放备份按钮。

## 5. 设置菜单

点击“设置”打开 Acrylic 菜单，顺序固定为：

1. 立即锁定
2. 启动保护…
3. 分隔线
4. 导入备份…
5. 导出加密备份…

“导出加密备份…”在没有账户时禁用。备份入口只从设置进入；账户导入方式仍全部位于“+”页面。

## 6. 添加账户页面

保持现有页面与业务行为：

- 返回按钮和标题“添加账户”。
- 主操作“截图并扫描二维码”。
- 次操作“从图片导入”。
- 次操作“手动输入”。
- 保留现有确认流程、错误 InfoBar 和不回显密钥的安全提示。

## 7. 账户行交互

账户行是一个统一的复制与手势交互区域，静止状态不显示独立复制按钮或操作按钮。

### 静止状态

```text
[图标] 账户名称                         123 456
       服务商 · 分组                    剩余时间
       ─────────────────────────────── 进度线
```

- 点击账号标签/账户行直接复制当前验证码。
- 复制成功后，仅在验证码位置显示“已复制”1 秒，然后恢复验证码。
- 不弹出全局成功通知，避免打断连续复制。
- 复制失败显示克制的“复制失败”提示；只尝试一次，不自动重试，不回显验证码或密钥。

### 左滑操作

- 鼠标、触控板或触摸向左拖动账户标签时，账户行向左滑出操作区。
- 操作区依次为“编辑”“查看密钥”“删除”。
- 操作区默认隐藏，不通过右键菜单访问。
- 松开手势后保持已揭示状态，点击账户主体或完成操作后收回；同一时间只允许一个账户行展开。
- “删除”属于破坏性操作，继续使用现有确认对话框和克制文案。

### 键盘与无障碍

- 账户行保留可聚焦语义、可访问名称和明显焦点状态。
- 复制、左滑和操作区状态需要为屏幕阅读器提供等价状态描述。
- 左滑不是唯一的语义线索；操作区在行获得焦点后应能通过标准键盘导航到达，但不新增右键菜单。

## 8. 安全锁定与解锁

### 锁定页

```text
应用已锁定

[使用 Windows Hello]

      使用电脑密码解锁
```

- 支持 Windows Hello 时，默认优先使用 Windows Hello。
- Windows Hello 不可用、设备不支持或验证失败时，提供“使用电脑密码解锁”。
- 不支持 Windows Hello 的设备直接将“使用电脑密码解锁”作为主操作。
- 电脑密码指 Windows 系统登录凭据；应用不保存、不读取、不自建密码。
- “启动保护…”设置说明为“优先 Windows Hello，不可用时使用电脑密码”。
- 手动“立即锁定”和启动保护共用同一解锁页面与失败提示。

## 9. 状态与验收标准

- 首页顶部除设置和“+”外没有第三个操作按钮。
- 首页底部没有备份/恢复按钮；导入备份和导出加密备份可从设置菜单找到。
- “+”页面仍能进入截图扫描、图片导入和手动输入。
- 账户行没有独立复制按钮，点击账户行能完成复制反馈闭环：验证码 → “已复制”（1 秒）→ 验证码。
- 右键账户行不再显示编辑、查看密钥、删除入口；向左拖动可以显示三项操作。
- 没有 Windows Hello 的设备可以使用电脑密码解锁；任何密码均不落盘。
- 浅色、深色、高对比度主题下，文字、焦点、拖动操作区和错误提示均可辨识。

## 10. 实现边界

- 优先复用现有 `AuthenticatorView`、`AddAccountView`、`MainWindow` 事件和服务，不改变账户数据模型。
- 将复制反馈、左滑状态和锁定页解锁方式作为可测试的状态，而不是依赖字符串匹配。
- 实现前先在 Figma 建立首页、设置菜单、账户行静止/复制/左滑、添加账户页和锁定页状态；再映射到 WinUI XAML。
